# 0.2.0 版本范围

[English](spec.md)

Robot Workflow 是可复用的开源工程依赖与证据工具，参考 Flow 的持续工程记录方向。本规范涵盖通用工具和最小示例。

- [交付边界](#交付边界)

## 必需行为

1. 提供领域无关的本地 CLI 和声明式依赖图配置；项目特定仓库不能硬编码到引擎中。
2. 记录精确 Git/文件溯源，区分基线与候选源码。
3. 检测相关源码语义变化，沿显式带类型的依赖边传播，提供依据和代表性路径。
4. 将组件实现状态与需求、绑定证据分开，明确显示 unknown、unverified 和 stale。
5. 提供交互工程工作流报告，包含源码变更、组件检查、版本组合、需求/证据、场景选择和中英文控件。
6. 包含可复用示例、许可证、构建元数据、自动测试、CI，以及完整成对的中英文结构化文档。

7. 不执行被检查源码，发现已有 checkout 与明确的跨仓库引用；推断边保留提供者到消费者方向与依据。
8. 提供简易初始化和启动命令，不覆盖已审查配置。
9. 轮询现有 checkout，获取并快进更新符合条件的干净分支；保留脏工作区、分叉和 detached checkout。
10. 通过环境变量配置的负责人 Webhook 路由有意义事件；持久保存投递重试，避免重复向已成功目标投递。

## 验证验收

- 使用版本化源码快照验证通用最小示例。
- 测试解析器类别、传递依赖传播、非语义注释、源码缺失和未登记变化。
- 验证最小安装、CLI/报告行为、源文件证据过期，以及可丢弃输入的完整恢复。
- 说明可用性优点、手工登记成本和未实现能力，不能从这些检查推断真机或全仓库兼容性。

## 交付边界

0.2.0 不执行训练、ROS 或物理命令，不包含 GitHub push Webhook 接收器、图编辑界面、CAD/PLM 集成或模型驱动的自主 agent。监测使用轮询与通用出站通知。验证源码、日志和历史快照保留在项目之外。公开发布需要可访问的仓库创建/push 路径；本地打包不能描述为已发布的 GitHub release。
